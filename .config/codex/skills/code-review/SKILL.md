# Code Review

PR またはローカル変更のコードレビューを実行する。主眼はバグ、リスク、挙動の退行、テスト不足の特定に置く。

## 対象

- 引数なし: 現在のローカル変更をレビュー
- `staged`: ステージ済み変更のみをレビュー
- PR 番号: `gh pr diff` で取得してレビュー
- コミットハッシュ: `git show` でレビュー
- `branch`: 現在ブランチとベースブランチの差分をレビュー
- ブランチ名: 指定ブランチとの差分をレビュー

## 差分取得の例

```bash
git diff HEAD
git diff --cached
gh pr diff <number>
git show <hash>
git diff $(git merge-base main HEAD)..HEAD
```

## レビュー手順

1. 対象差分を取得する
2. ファイルごとに変更点を読む
3. 全体の整合性、テスト、設計上の影響を確認する
4. 重大度順に指摘をまとめる

## 観点

- ロジックバグや境界条件の抜け
- 既存挙動の退行
- 例外処理やエラーハンドリングの欠落
- セキュリティ上の問題
- パフォーマンス問題
- テスト不足

## 出力方針

- 指摘を優先し、概要は短くする
- 可能ならファイルパスと行番号を示す
- 指摘がない場合はその旨を明記する
- 日本語で出力する
